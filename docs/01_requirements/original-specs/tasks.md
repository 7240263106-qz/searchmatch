## 一、存量能力处理与范围约束

1. **扩展而非重建**：为上传解析预览确认、审核发布、检索、报名入口、看板、智能体问答先补表征测试，再增量接入四层模型、正式数据范围、材料追溯和模型治理；保持既有 API 向后兼容。
2. **空库交付**：删除 `apps/api/prisma/seed.ts` 中竞赛系列、届次、赛道、候选、草稿、收藏、推送及演示统计写入；不得将旧“蓝桥杯”种子改名后作为真实验证结果，`dev.db` 不作为交付资产或证据。
3. **本期真实采集**：周期、手动、首次引导与验证触发均执行真实 HTTP；程序掌握 robots、限流、SSRF、下载、指纹、检查点、去重、权限和发布，模型只做语义建议。
4. **阶段边界**：只有订阅匹配、汇总、截止提醒和真实渠道投递为 P2；完整历史趋势与告警管理界面为 P2，但本期必须留存验收指标。自动采集、AI 页面理解、附件/快照、验证批次不得再标为二期。
5. **验收真实性**：单测可使用受控样本和假模型；真实联网验收不得用 mock、本地静态响应、内置样本或演示种子替代。环境不满足时必须标记“阻塞/待补验”，不得宣称通过。
6. **配置中心扩展而非重建**：任务 29～35 在既有 `process.env` 读取点与 `ModelProviderConfig` 上做替换，不重写采集编排、解析流水线或模型治理；`PARSER_URL`、`LLM_*`、采集常量、留存常量改为读 `ConfigResolver` 快照，`.env` 仅保留首启默认、紧急回退与密钥后端自身连接参数三类用途。配置保存与回滚不得写任何竞赛、候选、草稿、材料或统计对象。
7. **配置与业务分工**：信息源自身采集策略仍在任务 7（5.1）维护，模型调用账本与成本仍在任务 12/23（6.23）维护，配置中心只提供运行参数与生效、审计、回滚能力；采集总开关的唯一事实来源迁移到 `crawl.enabled`，`OnboardingState.crawlEnabled` 保留为兼容投影。

### 6.4 结论标注与交付边界

1. 只有全部步骤在目标环境实测且判据满足才记 `verified`；字段已实现但环境不具备真实条件记 `partial`；网络或依赖不可达记 `blocked`。
2. 任何 `partial`/`blocked` 都不得在发布报告、交付说明或验收记录中表述为“已通过”。
3. `realNetworkRequired=false`、缓存上次成功、本地 SQLite 推断 PostgreSQL、fake S3 推断真实桶切换，均不得作为通过证据。
4. 36～39 不新增配置项、不新增二级页、不新增数据表；既有 14 个配置接口路径与字段语义不变，新增能力只以只读接口或可选响应字段出现。

### 8.4 结论标注与交付边界

1. 只有 `verificationScope=real_outbound` 且判据满足、证据齐全才记 `verified`；`substitute` 记 `partial`；网络或依赖不可达记 `blocked`。默认模型静态解析、接口只增字段、门禁扫描等可离线验证项不受真实联网限制。
2. `blocked`/`partial` 不得在发布报告、交付说明、验收记录、页面徽标中表述为“通过/成功/已验证”，页面、测试连接响应与报告三处必须一致。
3. `realNetworkRequired=false`、模拟响应、桩服务、缓存上次成功、未实际外发，均不得作为 `real_outbound` 证据；`blocked`/`substitute` 不得映射 `success`。
4. 40～43 不新增配置项（仍 78/16）、不新增二级页、不新增接口（仍 16）、不新增模型 SDK、第二套协议适配器、第二张配置表或第二条业务调用路径；`presetId` 只进请求、响应、审计与调用记录，不落为配置项。
5. 任务 1～39 编号、依赖与完成状态不变；M6 36～39 的 `partial`/`blocked` 结论不受 M7 影响，M7 不把 M6 未完成项转记为通过。
6. 交付前更新追溯表：REQ-CONF-01～30、6.25.1～23、5.13.3 异常 1～25 均有承载任务与证据路径；所有缺口列责任人与补验环境，未验证项保留“未验证”标识且不阻止后续重测。
5. 配置保存、回滚、测试连接、凭据轮换、就绪重算与引导下发均不得写入竞赛、候选、草稿、材料、验证批次或统计对象；审计对象类型必须为 `system_config`。
